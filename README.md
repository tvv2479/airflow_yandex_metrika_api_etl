# Yandex Metrika API Hits ETL Pipeline

Репозиторий содержит **ETL-конвейер** (Data Pipeline) на базе **Apache Airflow**, который автоматизирует сбор сырых логов (просмотров / `hits`) из **Яндекс Метрики** через **Logs API**, выполняет их первичную очистку, трансформацию и распределяет по тематическим таблицам в **PostgreSQL (Staging DB)**.

## Архитектура и Процесс

Скрипт `hits_logs_ym` построен с использованием **Airflow TaskFlow API** (`@dag`, `@task`) и выполняет следующие шаги:

1. **Request Logs (`request_logs_ym`)**: 
   * Формирует POST-запрос к Logs API Яндекс Метрики для создания лога за прошлый день.
   * Ожидает завершения обработки запроса со стороны Яндекса (статус `processed`) с обработкой возможных временных ошибок сети и таймаутов.
   * Скачивает сырые данные (поддерживает многочастевую выгрузку, если данных много).
   * Очищает за собой очередь запросов на стороне Яндекса (`clean_log_request`).
2. **Transform & Load (`logs_to_db`)**:
   * Переводит сырой TSV-поток в `pandas.DataFrame`.
   * Нормализует названия колонок (заменяет двоеточия `:` на `_`, приводит к `lowercase`).
   * Приводит типы данных (идентификаторы в `string`, временные метки в `datetime`, очищает дубликаты).
   * Разрезает единый массив данных на **4 тематические таблицы** и загружает их в схему `ym` базы PostgreSQL методом `append`.

---

## Структура хранения данных (Схема `ym`)

Сырые логи просмотров разделены на 4 таблицы по бизнес-логике для оптимизации хранения и скорости выполнения аналитических запросов:

| Таблица | Описание | Ключевые поля |
| :--- | :--- | :--- |
| **`ym.ym_hits_obshee`** | Основные данные просмотра | Дата/время, Title, URL, География (Город, Страна) |
| **`ym.ym_hits_ad`** | Маркетинговые и рекламные метки | Все UTM-метки, Openstat, Источники трафика, GCLID |
| **`ym.ym_hits_events`** | Цели, параметры и события | Массивы GOALS ID, Ecommerce-данные, ParsedParams |
| **`ym.ym_hits_tech`** | Технические характеристики устройства | Браузер, ОС, Экран, IP-адрес, Сеть |

*Все таблицы связаны составным первичным ключом (`PRIMARY KEY`):* `(ym_pv_datetime, ym_pv_watchid, ym_pv_clientid, ym_pv_counteruseridhash)`.

## Стек технологий

* **Оркестрация:** Apache Airflow 3.x+ (TaskFlow API)
* **Язык разработки:** Python 3.10+ (`pandas`, `pendulum`, `sqlalchemy`)
* **База данных:** PostgreSQL
* **Источник данных:** Yandex Metrika Logs API v1

## Настройка и запуск

### 1. Подключения в Airflow (Connections)
В веб-интерфейсе Airflow необходимо создать два подключения:

* **`ym_token_logs`** (Тип: `HTTP`):
  * `Password`: Ваш OAuth-токен Яндекс Метрики.
* **`staging_db`** (Тип: `Postgres`):
  * Параметры подключения к целевой базе данных PostgreSQL.

### 2. Развертывание таблиц
Перед запуском DAG необходимо применить SQL-скрипт инициализации таблиц и индексов из файла `init_db.sql` *(или укажите ваш путь к файлу структуры)*. 

### 3. Расписание (Schedule)
По умолчанию DAG настроен на ежедневный запуск в **07:15 утра по НСО (Новосибирск, UTC+7)** / `15 2 * * *` по UTC, собирая данные за **вчерашний день** (`days=1`).

## Логирование и отказоустойчивость
* Конвейер снабжен детальным логированием каждого шага (`Step_1` – `Step_4`).
* Для скрытия чувствительных данных из UI Airflow на этапе скачивания логов используется параметр `show_return_value_in_logs=False`.
* В случае сетевых сбоев со стороны API настроен перезапуск: `retries: 1` с паузой в `5 минут`.
